# Akira Kojima Portfolio

小嶋明のポートフォリオサイトです．`main` ブランチのルートをGitHub Pagesで公開しています．

- 公開URL: https://kojima8924.github.io/
- 実装: 単一の `index.html`，Bootstrap 5，Vanilla JavaScript
- 主な内容: 研究，受託開発，生成AI不使用のCG自力実装，AIエージェントを活用した個人開発・OSS
- このREADMEはリポジトリ内の実装を説明します．ローカル変更が公開サイトへ反映済みかどうかは，GitとGitHub Pagesの状態を別途確認してください．

## ファイル構成

- `index.html`: ページ本体．CSSとJavaScriptも含む
- `media/`: 作品画像，OGP画像，配布用PDF
- `make_pdf.py`: 同じHTMLからA4 PDFを生成するスクリプト（採用向け／完全版の2モード）
- `make_ogp.py`: HTML/CSSだけで1200×630のOGP画像を生成するスクリプト
- `scripts/check_portfolio.py`: リンク・alt・表記揺れなどの自動検査
- `scripts/import_figures.py`: 帯図（`media/fig/*.svg`）をslideリポジトリのPDFから変換して取り込む
- `docs/`: 検証ログ（`verification/`）と，外部ページで対応する項目のメモ
- `requirements-pdf.txt`: PDF・OGP生成と図版検査用のPython依存
- `proposal/`，`tmp/`: 試作・目視確認画像などのローカル作業領域．誤公開防止のためGit管理対象外

## サイト構成

短いプロフィール・資格・連絡導線 → 研究 → 受託案件 → CGの自力実装 → AI活用の個人開発・OSS → 詳細経歴 → 補足作品 → 連絡先，の順に読める構成です．DOM順と視覚順は一致させ，CSSの`order`で内容を並べ替えません．

- 冒頭は人物像と主な実績，メール・GitHub・PDFなどの確認手段を短く示します．詳細な年表や，各作品で共通する説明を繰り返して冒頭を長くしません．
- 研究・CGにおける本人の自力実装と，現在の受託・代表OSSにおけるAIエージェントへの実装委任を明示的に区別します．「製品がAIを使うこと」と「開発時に生成AIを使うこと」は別の軸です．生成AI不使用を，機械学習やライブラリ自体の不使用とは表現しません．
- 研究は，本人の実装・解析・評価と，共同研究での担当範囲，論文・発表，条件付きの定量結果を示します．研究数値は「従来法の約21%まで低減」「最悪領域のHWHMを19.2%低減（16電極のシミュレーション）」で統一します．21%は2026-09-17に生データから再計算した値です．経緯と根拠はCVリポジトリのREADMEを参照してください．
- 受託案件は，美容クリニック向けLINE応答AIの開発事例です．施設を特定しない範囲で掲載許可を得ており，顧客名・画面・利用者データは公開しません．開発者PC上の試作環境で，本番導入前という状態を維持して記載します．
- 受託の評価結果は通常のHTML本文でも読めるようにします．14,051会話の匿名化処理，限定した7設問・確認項目26点での回答網羅率50%→81%，平均応答時間12.4→6.5秒，プロジェクト全体のpytest395件などは，測定条件・検証範囲と一緒に扱います．機械検査の通過を完全な匿名化保証へ読み替えません．
- Pythonレイトレーシング，シャドウマッピング，GLSL＋CSGのCG3作品は，生成AI不使用の自力実装として画像付きで常時表示します．以前の「過去作品10件」の折りたたみに埋もれさせません．その他の作品と追加画像・説明は，補足として展開できる構成です．
- AI活用作品はTrivium，ScriptVEdit，Clage Cookを主要事例とし，ChromiumforAなどを補足として扱います．作品ごとの設計判断・担当・検証条件は残し，共通説明や画像の重複を減らします．ScriptVEditの異なる条件のベンチマークは，単純な並列化効果として合算・比較しません．
- 技術バッジはCSS製の自前バッジです．shields.ioへの外部通信はありません．資格のAWS Certified AI Practitionerデジタルバッジは，Credlyの検証ページへリンクします．発行元画像を縮小したもので，図柄を改変しません．
- AWSでの質問対応など，未実装の構想は稼働中の機能として掲載しません．

## 図・画像と内容の同期

帯図の正本は `C:\code\slide\cases\2026-09-18_CV・ポートフォリオ図版\` と `C:\code\slide\cases\2026-09-18_履歴書用_受託案件構成図\` にあります．文言の根拠は，そこにある`facts.md`と各リポジトリの記録です．本人の担当範囲や評価条件は，正式な履歴書・職務経歴書とも照合します．

図そのものを変更する場合は，slide側の正本を直して`slide.py check`でPDFを作り直し，`scripts/import_figures.py`で取り込みます．文字がパス化されたSVGを直接書き換えたり，元図の意味が変わるように部分加工したりしません．

受託の改善実績については，旧`clinic-results.svg`の文言をページ内の最新説明として再利用せず，条件を明示したHTMLの指標表示を使います．元図と参照元PDFは保持し，今回の変更だけのために別リポジトリの正本を書き換えません．構成図など，引き続き掲載する帯図は既存の同期手順を維持します．

スマホでも要点を本文で読めることを優先し，図の全体表示と拡大表示を区別します．図のモーダルには拡大・縮小・全体表示の操作を用意し，拡大時は内部を横スクロールして読めます．画面内へ縮小しただけの表示を，文字を読むための拡大の代わりにしません．PC・スマホの双方で，画像領域の予約，キャプション，操作・リンクの識別，ライト／ダーク表示を確認します．

シャドウマッピングの閲覧用画像`media/shadowmap.jpg`は1200×1200pxです．5000×5000pxの原画像からPillowのLanczos法で単純縮小し，JPEG品質92・色差サブサンプリングなしで保存しています（生成AI・構図変更なし）．履歴書からの直リンクURLは維持します．原画像は`C:\code\CV\assets\cg\shadowmap.jpg`とGit履歴に保管し，印刷用PDF・CV内の画像は変更しません．

OGPは生成AIを使わず，`make_ogp.py`のHTML/CSSから同じブラウザー・フォント環境で再現可能な形で描画します．研究・受託・自力CG・AI活用の4領域と，それぞれの担当範囲が本文と一致するように保ちます．

## PDF・OGPの再生成

初回だけPlaywrightとChromiumを用意します．

```powershell
python -m pip install -r requirements-pdf.txt
python -m playwright install chromium
```

HTMLを確定した後，次のコマンドで2種類のPDFを更新します．

```powershell
python make_pdf.py            # 両方生成（--mode summary|fullで個別生成）
# media/Akira_Kojima_Portfolio_Summary.pdf  採用向け
# media/Akira_Kojima_Portfolio.pdf          完全版
```

スクリプトはローカルHTTPサーバーを一時的に起動し，折りたたみを全展開して印刷対象画像の読込を確認してからA4 PDFを生成します．採用向けは`body.pdf-summary`を付与し，`.pdf-full-only`と`.summary-hide`の補足要素を省きます．本文と同じ担当範囲・評価条件を維持し，自力CGの証拠やAI委任の説明を丸ごと落とさないことを確認します．

採用向けはA4 2ページを目標にしますが，ページ数・サイズは生成時の実測値で確認します．旧版の「2ページ／9ページ」やファイルサイズを，新版の検証結果として流用しません．再生成後に，本文・画像・キャプションの同居，孤立見出し，改ページ，リンク，AI委任と実装経験の区別を全ページで目視確認してください．

生成後，埋め込み画像を150dpi・JPEG品質80へ再圧縮し，実ページ数を表示します．資格バッジと小さいサービスロゴは保護します．`--source`，`--output`，`--timeout`で入出力と待ち時間を変更できます．

PDF生成用の一時ローカルサーバーを参照するリンクは，後処理で公開URLへ変換します．外部URL・`mailto:`・PDF内の移動先は変更しません．この区別は回帰テストで検証します．

SNS共有画像は，同じPlaywright環境でHTML/CSSから描画します．

```powershell
python make_ogp.py
# media/ogp-portfolio.png
```

生成した1200×630px画像の文字切れ・重なり・余白を目視確認し，OGPのtitle・description・altもページ内容と同期します．

## 自動検査

```powershell
python scripts/check_portfolio.py             # HTML内部の検査
python scripts/check_portfolio.py --external  # 外部リンクの到達確認も行う
python scripts/import_figures.py --check      # 図版の参照元PDF欠損・SVGの更新要否を確認
python -m unittest discover -s tests -v       # 検査スクリプトの回帰テスト
```

重複ID，内部anchor切れ，ローカル参照切れ，alt欠落，`rel`不足，shields.io残存，プロジェクト名の表記揺れ，研究数値の誤解表現などを検査します．AtCoder／paizaの表記検査は表示テキストにのみ適用し，URLを誤検出しません．

`import_figures.py --check`は参照元PDFからSVGをメモリ内で生成し，改行を正規化して既存SVGと内容を比較します．参照元PDF・出力SVGの欠損，または内容の差異があれば終了コード1を返します．内容比較にはPyMuPDFが必要です．ファイルの更新時刻は判定に使いません．

通常の取り込みでも対象PDFを最初にすべて検証し，欠損があれば何も変換しません．各SVGは同じディレクトリの一時ファイルへ書き終えてから置換するため，書き込み途中の失敗で既存SVGが壊れることを防ぎます．

保存済みの結果と実行時点は`docs/verification/README.md`を参照してください．旧ログは履歴として残し，未実行の検査や公開反映を新しい版で成功済みとは記録しません．

2026-09-20のローカル改修では，内部検査・外部18リンクの到達確認・図版同期に問題はなく，単体テスト41件が成功しました．PC 1440×1000とスマホ相当390×844のライト／ダークを撮影して確認し，320／360／390／768／1024／1440pxの各幅・両テーマでページ全体の横はみ出しがないことを確認しました．Android実機・エミュレータ，今回版のaxe-core／W3C Nu，ニコニコ動画の埋め込み実再生は未検証です．詳細とPDFの最終受入状況は検証READMEを参照してください．

## 更新時の確認

1. 本文・画像・alt・OGP・PDF2種類の内容を揃える．帯図を変える場合だけ，slide側の正本から再生成して取り込む．
2. 内部検査，図の同期確認，回帰テストを実行する．必要に応じて外部リンクも確認する．
3. PC／スマホ，ライト／ダークを撮影し，図の拡大，ナビ，折りたたみ，キーボード操作，ページ全体の横はみ出しを確認する．
4. PDFの全ページを画像として確認し，実ページ数・サイズと確認結果を記録する．
5. 作品画像，GitHub，論文，動画，メールのリンク先を確認する．作品名リンクは該当作品へ直接移動させる．
6. 顧客情報，未確認の成果，担当範囲を誤解させる表現がないことを確認する．
7. `proposal/`，`tmp/`や未公開素材がGit差分に入っていないことを確認する．push・公開は明示的に依頼された場合だけ行う．
