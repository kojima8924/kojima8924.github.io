# Akira Kojima Portfolio

小嶋明のポートフォリオサイトです．`main` ブランチのルートをGitHub Pagesで公開しています．

- 公開URL: https://kojima8924.github.io/
- 実装: `index.html`，Bootstrap 5，Vanilla JavaScript．質問対応とメディア拡大表示のJS/CSSは同一オリジンの`assets/`へ分離
- 主な内容: 研究，受託開発，生成AI不使用のCG自力実装，AIエージェントを活用した個人開発・OSS（このサイトのAI質問機能を含む），キムワイプ卓球会での活動・発表
- このREADMEはリポジトリ内の実装を説明します．ローカル変更が公開サイトへ反映済みかどうかは，GitとGitHub Pagesの状態を別途確認してください．

## ファイル構成

- `index.html`: ページ本体．CSSとJavaScriptも含む
- `assets/assistant.js`，`assistant.css`: 質問対応のモデル選択・会話・ダイアログUI
- `assets/assistant-site.js`，`assistant-site.css`: このサイト用の接続設定と本文内への配置
- `assets/media-viewer.js`，`media-viewer.css`: 作品画像・動画の共通拡大ビュー，画像の拡大・前後切替と説明
- `tests/`: Pythonの検査・PDF回帰テストと，Node標準機能だけで動く質問対応UI・メディア表示のテスト
- `media/`: 作品画像，OGP画像，配布用PDF
- `make_pdf.py`: 同じHTMLからA4 PDFを生成するスクリプト（採用向け／完全版の2モード）
- `make_ogp.py`: HTML/CSSだけで1200×630のOGP画像を生成するスクリプト
- `scripts/check_portfolio.py`: リンク・alt・表記揺れなどの自動検査
- `scripts/import_figures.py`: 帯図（`media/fig/*.svg`）をslideリポジトリのPDFから変換して取り込む
- `scripts/crop_research_recon.py`: Git履歴の高解像度ポスターから研究の比較図を再切り出しする
- `docs/`: 検証ログ（`verification/`）と，外部ページで対応する項目のメモ
- `requirements-pdf.txt`: PDF・OGP生成と図版検査用のPython依存
- `proposal/`，`tmp/`: 試作・目視確認画像などのローカル作業領域．誤公開防止のためGit管理対象外
- `.codex-remote-attachments/`: 会話で共有された原本．一括公開を避けるためGit管理対象外とし，採用したファイルだけを`media/`へコピーする

## サイト構成

短いプロフィール・資格・連絡導線 → AI質問対応（β・品質検証中） → 研究 → 受託案件 → CGの自力実装 → AI活用の個人開発・OSS（AI質問機能の作品紹介を含む） → 詳細経歴 → サークル活動・発表 → 補足作品 → 連絡先，の順に読める構成です．DOM順と視覚順は一致させ，CSSの`order`で内容を並べ替えません．

## AI質問対応の組込み状態

2026-09-29のローカル変更では，質問欄をプロフィールの後・研究の直前へ移し，見出しを「AIに作品・経歴・小嶋明について質問する」としました．研究・作品・経歴だけでなく，公開資料にある経験・活動・開発の考え方も質問対象とし，未記載のことや私的な情報は扱わない旨を明記しています．β版・品質検証中であること，担当・実績を推測で補わない方針と誤回答の可能性，参照元の確認，質問によって回答できない場合があることを案内します．ナビゲーションの「AIに質問」からも移動できます．質問欄と対応するナビ項目は印刷・PDFに出しません．

`index.html`冒頭の`meta[name="portfolio-assistant-endpoint"]`に`https://9m4lkt83ab.execute-api.ap-northeast-1.amazonaws.com`を設定し，2026-09-29に初回βをGitHub Pagesへ反映しました．公開ページでβ案内・起動ボタン・Qwen既定の3モデル一覧を確認済みです．接続先をURLパラメータやブラウザの保存領域から受け取らず，HTTP・資格情報付きURL・クエリ付きURLは拒否します．起動ボタンは作品の閲覧を遮らないよう本文内に置き，画面右下へ固定しません．参考用の模擬プレビューの右下固定ボタンとは意図的に配置を分けています．JavaScript無効時は，質問欄にJavaScriptが必要である旨と各作品リンクへの案内が残ります．metaを空欄にした場合は準備中案内だけとなり，質問入力・起動ボタン・API通信は作りません．

設定後もページ読込時には通信しません．利用者がボタンを開いたときだけ利用可能なモデルを取得し，質問の明示送信時だけ回答を要求します．モデル確認後は選択中モデル名を含む初回案内と質問例3件を表示しますが，初回案内はAPI履歴に含めません．根拠付き回答に次質問候補がある場合は最大3件をボタン表示し，押した候補は通常の質問として1回だけ送信します．候補のための追加通信，自動再送，別モデルへの自動切替はしません．モデル変更では会話を消さず，新APIでは次の送信に直近8往復を引き継ぎます．画面のログは8往復より古い分も，回答モデル名・出典付きでページを開いている間は残します．APIへ送る過去回答は各1,500文字までです．ページ再読み込みまたは明示的な会話リセットでログと文脈を消し，全モデル共通の利用回数は引き継ぎます．回答と候補はHTMLとして挿入せず，参照元は資格情報を含まないHTTPSリンクに限定します．この欄とダイアログは印刷・採用向けPDFでは非表示です．

UIの共通JS/CSSを更新する際は質問対応側の正本と照合し，コピーを同期して両側のテストを行います．`tests/assistant-site.test.cjs`は，公開構成の明示URLと，未設定時に初期化も通信もしない挙動を分けて検査します．設定を消すことはUIの無効化であり，公開APIそのものの停止ではありません．

共通UIの起動ラベル・質問対象の説明・入力例を両側で揃えています．検索はAWS，回答生成は選択モデルに応じたAWS・OpenAI・Anthropicで行い，質問・APIが通知した範囲の直近会話・検索した公開資料を生成先へ送信する案内へ整合しました．新APIは直近8往復・全モデル共通40回／IP／UTC日を `GET /models` で通知します．2026-09-30に本番APIをこの新仕様へ更新し，`interaction` と次質問候補 `suggestions` を返すことを公開URLで確認しました．対話設定を返さない旧APIには4往復・20回で安全に接続する互換を残しているため，将来API側だけが巻き戻っても5問目以降を不正な履歴件数で停止させません．実際の送信先・処理地域・保持条件はAPIから返すモデル別の案内を表示し，モデル変更時にも更新します．切替だけでは送信せず，次の送信時に他モデルとの会話も新しい選択先へ渡ること，引き継ぎたくない場合は送信前にリセットすることを説明します．ブラウザに各社APIキーを渡さず，通信先は引き続き同じ公開APIです．ローカル試用専用の通信・期限・認証コードは混ぜません．

初回βはAWS上のQwenを標準，GLM 5・Kimi K2.5を参考比較用として公開し，同日後続でGPT-5.6 Terra（OpenAI）・Claude Sonnet 5（Anthropic）も追加しました．Qwenを初期選択に保ち，APIの`/models`が返した有効モデルだけを表示します．5モデルの公開HTTP回答と，実ブラウザでの5モデル一覧・Qwen既定・モデル別送信先表示を確認済みです．全モデルとも品質検証中で，有限な疎通確認は包括的な品質保証ではありません．既知の情報不足・未回答・長い説明等を残し，誤りの可能性と参照元確認の案内を維持します．直API鍵をブラウザへ渡さず，片方の鍵取得失敗を既存3モデルへ波及させない構成です．

公開画面はPC 1280×900とスマホ相当390×844で確認し，スマホのダイアログは横にはみ出さず，縦スクロールで送信ボタンまで到達しました．ブラウザからの実質問は送信結果が不確定となり，二重送信を避けて追加検証を止めたため，ブラウザ経由の回答・引用表示は未確認です．API側のHTTP試験とUI表示確認を区別します．

## 作品画像・動画の操作

作品メディアは通常クリックで同じページ内の拡大ビューを開きます．サムネイル右下に，動画は「▶ 動画を見る」，画像は「⤢ 画像を拡大」を常時表示します．ScriptVEditの主画像は解説動画への導線，補足の構文・性能画像は静止画の拡大です．シャドウマッピングも他の画像と同じ拡大操作に揃え，資格バッジ・GitHub・論文・サービスのリンクは対象にしません．

同じ作品の画像は前後に切り替え，説明と位置を表示します．拡大・縮小・全体表示を備え，長い画像や図はビュー内をスクロールして読めます．閉じるボタンとEscを用意し，閉じたら動画を止めて元の操作位置へフォーカスを戻します．外部動画フレーム内のキー入力は親ページへ届かない場合があるため，画面内の閉じるボタンも維持します．

動画フレームは利用者が開いたときだけ読み込みます．配信側の制約などで再生できない場合に備え，「配信元で見る」を補助リンクとして残します．元の画像・動画URLも`href`に保持し，JavaScriptなしや修飾キーを伴う操作では通常リンクとして利用できます．操作ラベルと拡大ビューは印刷・PDFでは非表示にします．

## PDF・OGPの再生成

初回だけPlaywrightとChromiumを用意します．

```powershell
python -m pip install -r requirements-pdf.txt
python -m playwright install chromium
```

HTMLを確定した後，次のコマンドで2種類のPDFを更新します．

```powershell
python make_pdf.py            # 両方生成（--mode summary|fullで個別生成）
# media/Akira_Kojima_Portfolio_Summary.pdf  採用向け
# media/Akira_Kojima_Portfolio.pdf          完全版
```

スクリプトはローカルHTTPサーバーを一時的に起動し，折りたたみを全展開して印刷対象画像の読込を確認してからA4 PDFを生成します．採用向けは`body.pdf-summary`を付与し，`.pdf-full-only`と`.summary-hide`の補足要素を省きます．本文と同じ担当範囲・評価条件を維持し，自力CGの証拠やAI委任の説明を丸ごと落とさないことを確認します．

採用向けはA4 2ページを目標にしますが，ページ数・サイズは生成時の実測値で確認します．旧版の「2ページ／9ページ」やファイルサイズを，新版の検証結果として流用しません．再生成後に，本文・画像・キャプションの同居，孤立見出し，改ページ，リンク，AI委任と実装経験の区別を全ページで目視確認してください．

生成後，埋め込み画像を150dpi・JPEG品質80へ再圧縮し，実ページ数を表示します．資格バッジと小さいサービスロゴは保護します．`--source`，`--output`，`--timeout`で入出力と待ち時間を変更できます．

PDF生成用の一時ローカルサーバーを参照するリンクは，後処理で公開URLへ変換します．外部URL・`mailto:`・PDF内の移動先は変更しません．この区別は回帰テストで検証します．

SNS共有画像は，同じPlaywright環境でHTML/CSSから描画します．

```powershell
python make_ogp.py
# media/ogp-portfolio.png
```

生成した1200×630px画像の文字切れ・重なり・余白を目視確認し，OGPのtitle・description・altもページ内容と同期します．

## 自動検査

```powershell
python scripts/check_portfolio.py             # HTML内部の検査
python scripts/check_portfolio.py --external  # 外部リンクの到達確認も行う
python scripts/import_figures.py --check      # 図版の参照元PDF欠損・SVGの更新要否を確認
python -m unittest discover -s tests -v       # 検査スクリプトの回帰テスト
node --test tests/assistant.test.cjs tests/assistant-site.test.cjs  # 無通信の質問対応UI検査
node --test tests/media-viewer.test.cjs       # 無通信のメディア表示検査
```

重複ID，内部anchor切れ，ローカル参照切れ，alt欠落，`rel`不足，shields.io残存，プロジェクト名の表記揺れ，研究数値の誤解表現などを検査します．AtCoder／paizaの表記検査は表示テキストにのみ適用し，URLを誤検出しません．

`import_figures.py --check`は参照元PDFからSVGをメモリ内で生成し，改行を正規化して既存SVGと内容を比較します．参照元PDF・出力SVGの欠損，または内容の差異があれば終了コード1を返します．内容比較にはPyMuPDFが必要です．ファイルの更新時刻は判定に使いません．

通常の取り込みでも対象PDFを最初にすべて検証し，欠損があれば何も変換しません．各SVGは同じディレクトリの一時ファイルへ書き終えてから置換するため，書き込み途中の失敗で既存SVGが壊れることを防ぎます．

保存済みの結果と実行時点は`docs/verification/README.md`を参照してください．旧ログは履歴として残し，未実行の検査や公開反映を新しい版で成功済みとは記録しません．
