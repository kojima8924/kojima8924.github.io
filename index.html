Clage Cook — 4つのAIを、1つの会議へ（OSS）

Repo
デスクトップ版（Windows）で実行した会議。各AIのモデル名・所要時間・DEBATEの実施状況が並び、 下に実測トークン台帳と統合回答が続く。右上の「DIRECT · LOCAL」は、APIキーと会話を端末内だけで扱っている状態を示す

1つの質問を Claude・Gemini・ChatGPT・Grok へ同時に送り、4つの回答を 見比べたうえで1つの「統合回答」にまとめるAI会議アプリ。回答は出来上がった順に リアルタイムで届く（SSE: サーバーからの逐次配信）。回答者どうしが互いの回答を 批評してから書き直すDEBATE、AI名を伏せて先入観を消すBLINDを搭載。

利用者自身のAPIキーで動くBYOK方式のため、課金の安全設計を重視: 送信前に「何回APIを呼び、最大何トークン使うか」を端末側で計算して確認をとってから実行し、 同じリクエストの再送では課金処理を繰り返さない。使用量は各AIが実際に返した実測値だけを 記録し、推定値で埋めない。

1社が失敗しても他の回答は失われず、APIキーと会話履歴は端末内に留まる（サーバーへ送らない）。

技術
  • Flutter（6プラットフォーム） + FastAPI / SSEストリーミング
  • 4AI並列実行・1社失敗時も他の回答を保持（部分成功）
  • 相互批評（DEBATE）/ 匿名化（BLIND）/ 回答間の語彙一致度の可視化
  • 実行前の呼出回数・トークン上限計算と課金確認・二重課金防止
  • 自動テスト バックエンド313件 + アプリ140件
同じアプリのAndroid版。回答を開くと、DEBATEで書き直す前の回答も残っている

ChromiumforA — 検索結果をAIが読み、並べ直すAndroid版Chromium（非公開）

Private

Android版Chromiumをソースからフルビルドし、ブラウザ本体（C++）まで改造した 自分専用ブラウザ。全ページへ自作JavaScriptを注入し、自宅PCのFastAPIブリッジ経由で AIを呼ぶことで、拡張機能だけでは作れない機能を実装している。

代表機能は検索結果のAI再評価。候補ページを実際に読んで信頼性・有用性を 評価し、根拠コメントを各カードへ差し込み、取得済み情報を加味して順序を組み替える。 純正カードを複製せずDOM上で移動するため、Googleの見た目とテーマは保たれる。 ほかに、ページのファクトチェック色分け、自然言語から生成したサイト専用CSS/JSの 継続適用、選択テキストへのAI質問を実装。

セキュリティ設計: 開発中、ページ側のJSから内部トークンを奪取できる 脆弱性を自分で発見。ページから読み書きできない分離ワールド（ブラウザがサイトのJSと 隔離して実行する環境）だけを通してコマンドを受け渡す構造へ再設計し、攻撃経路を 構造的に遮断した。防御が効いていることを実機で確認できるセルフテストページも実装。

技術
  • Chromiumフルビルド（C++/Java改造・独自 chrome://flags 追加）
  • 注入JS ↔ ブラウザ本体の往復RPC（実測 約30ms）
  • FastAPIブリッジ / Tailscale経由で外出先からも同一アドレスで到達
  • 分離ワールド+共有トークンの多層防御・セルフテストによる実機検証

※個人環境（自宅PC連携）前提の構成のためコードは非公開。ここでは画面と設計で紹介。

scriptvedit — AIが自分で使い、自分で拡張する動画編集DSL

Repo ▶ Video
左のコードが、右の映像をそのまま生成している場面（解説動画より）。 表示しているコード文字列を実際に実行して右側を描いているので、コードと映像が食い違わない

この解説動画は、AIがscriptveditを使って自動生成したもの。 scriptveditはPythonコードで動画を組み立てるDSL（目的特化の記述言語）で、 AIに全工程を委任できるよう設計している。編集中に「こういう字幕・演出が欲しい」と なったら、AIがその場で機能をプラグインとして実装し、次のカットからすぐ使う—— 道具を使いながら道具を拡張するワークフローを実運用している。

技術面では、演算子オーバーロード（|, &, <=）による 直感的な記述を、FFmpegの式システムへコンパイルしてフレーム単位で評価する。

技術
  • 演算子オーバーロードDSL / AST→FFmpeg式コンパイラ
  • 27種イージング / キーフレーム補間 / シーケンス制御
  • 符号付き距離場によるモーフィング / VOICEVOX音声合成
  • 時間分割並列レンダ（この動画で1012秒→106秒）
  • AIによるプラグイン自動追加を前提とした拡張設計
高速化の実測値も動画内で紹介。数字はこの動画自身を計測したもの

Clage Cook Original — 4AI会議の母艦（非公開・毎日運用）

Private

OSS版の原型となった、自宅サーバ常駐の個人環境版。Androidアプリ（Kotlin/Compose）から 質問を送ると、PC上のサーバが4つのAIを並列実行して統合回答を返す。

生成中の途中経過配信、停止ボタン、アプリを閉じても続く生成と開き直したときの復帰、 会話ごとの文脈維持、4サービスの使用量を一目で見るホーム画面ウィジェットなど、 毎日使う道具としての操作感をここで作り込んだ。 この設計・UIの知見を、各社公式APIだけで動く公開版（上のOSS）として再実装している。

技術
  • Kotlin / Jetpack Compose + FastAPI / SSE
  • 生成の停止・切断後の再接続・進行中会話の復帰
  • 使用量ウィジェット（タップ更新・取得制限時の直近値表示）
  • Wi-Fi / Tailscale の自動フェイルオーバー接続

Calcpy — 電卓×Python（プロトタイプ）

Private

「電卓の使用感を保ったまま、必要なところだけPythonへ広げる」Android関数電卓。 sin(pi/4) と入力すると 0.707… ではなく √2/2 と 厳密解で返る（SymPy）。

数学関数は6つの4方向フリックハブに収め、タップでレイヤー循環・ 長押しで候補表示という独自の入力方式を設計。Python実行はUIと別プロセスに 隔離し、暴走時はタイムアウトで切る。日常使いできる最小形を検証中。

技術
  • Jetpack Compose / Chaquopy（端末内CPython 3.13）
  • SymPy厳密計算 / セル型REPL（.pyファイルが正本）
  • フリックハブ入力・別プロセス隔離実行

研究

畳み込みニューラルネットワークによる接触抵抗式トモグラフィ型触覚センサの空間分解能の向上

SI2022（国内）およびIROS 2022（国際）にてポスター発表を行った。
電気インピーダンストモグラフィに基づく触覚センサにおいて、シミュレーションで生成した訓練データを用いて畳み込みニューラルネットワーク(CNN)を学習させ、限られた計測電位から高精度な圧力分布の再構成を実現し、空間分解能の向上を達成した。
実機での2点接触実験を踏まえ、訓練データに与えるノイズレベルを調整し、2点を弁別可能にした。
1点の接触シミュレーションにおいては、CNNの導入により、空間分解能と位置誤差が約22%まで改善された。
ロボットハンドの把持制御や医療応用への展開が期待される技術である。

Authors: Akira Kojima, Shunsuke Yoshimoto, Akio Yamamoto
技術
  • 電気インピーダンストモグラフィ (EIT)
  • 畳み込みニューラルネットワーク (CNN / Keras)
  • シミュレーションによる訓練データ生成
  • 圧力分布再構成

Optimization of electrode positions for equalizing local spatial performance of a tomographic tactile sensor
（トモグラフィ型触覚センサの局所空間性能を均一化に向けた電極位置の最適化）

論文ページ

Frontiers in Robotics and AI に掲載された査読付き論文。
接触抵抗式トモグラフィ型触覚センサにおいて、検出領域全体で均一な空間分解能を実現するための電極配置の最適化手法を提案した。
接触位置によって空間性能にばらつきが生じる課題に対し、電極間隔を調整するアルゴリズムを開発。16電極・64電極の構成でシミュレーション評価を行い、等間隔配置と比較して最も空間分解能の低い接触点の性能がそれぞれ0.81倍・0.93倍に改善された。

Authors: Akira Kojima, Shunsuke Yoshimoto, Akio Yamamoto
技術
  • 電極配置最適化アルゴリズム
  • 接触抵抗式トモグラフィ型触覚センサ
  • 空間分解能の均一化シミュレーション
